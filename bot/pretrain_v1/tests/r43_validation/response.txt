R43-01: _run creates and retains out/claims before launching supervisors.

R43-02: readiness is bounded to 120 seconds, including each successor handshake.
At six hours, the parent closes exposure and cancels supervisor receive/send waits.
The independent host/RSS/lease and physical-GPU monitors remain active through
worker and learner shutdown. WorkerSession retains exact PID/start/session records,
scans before reaping the leader, adopts/reaps orphan descendants via the existing
subreaper and uses identity-checked pidfds for signals. The pinned Python has no
pidfd wrappers, so the implementation calls the x86_64 Linux syscalls directly.
Each session gets 10 seconds for clean exit, five for TERM and five for KILL/reap.
Any signal, nonzero exit, missing identity, unreaped session or cleanup failure
fails qualification. The independent monitor also escalates while a receiver or
coordinator condition is stuck. Supervisor/learner waits share a 150-second
shutdown budget. Monitor joins and counter locks are separately bounded. If an
in-process adapter/optimizer/monitor cannot stop, CleanupIncomplete makes the
entry process exit 2, preventing a stuck Python thread from keeping it alive.
No diagnostic checkpoint is written after failure; stopped counts and errors are
retained. The external R37 watcher and outer operational hard timeout remain
required. User-space deadlines do not make uninterruptible kernel I/O cancellable.

R43-03: complete framed send and receive use nonblocking I/O and one monotonic
deadline, covering partial headers, partial bodies, empty/stalled ACKs and full
send buffers. Stop checks run at most 50 ms apart while awaiting readiness.
Frames retain multiprocessing.Connection's small-message wire format and 1 MiB
cap. Ordinary sends have a 30-second cap, worker ACKs retain the configured finite
collection timeout with stop cancellation, and parent stop notification has a
200 ms cap. No transport or cleanup helper thread is created.

R43-04: permit/spec construction, initial transport queue creation, descriptor
setup, process spawn and registration are all inside the supervisor's owning
exception/cleanup boundary. Every supervisor error records a failure and requests
coordinator stop immediately. Stop/learner events precede counter/condition work;
condition acquisition is bounded and the independent monitor retries abort.
The startup-error regression creates a genuine filesystem collision for one
spool after another real fixture child has reported ready.
