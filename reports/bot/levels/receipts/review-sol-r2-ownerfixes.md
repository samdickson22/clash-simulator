Any incidental config differences from entity strings are not an asserted coverage guarantee. A passing run can therefore miss stale config reuse across level changes, the exact risk this gate was meant to discharge. Add a bounded explicit A → B → A sequence on this same worker, assert different config content/keys for A/B and actual reuse for the final A, and compare all three to their own uncut references. Keep the existing two-slot reservation. This is a fixture requirement; it does not authorize pooled live use or resolve native metadata design.

2. **P1, gate coverage — successful casts do not establish the advertised payload fixtures.** `bot/levels/gates.py:191–195` now records failed casts as FAIL, which fixes the prior silent-hand failure. But `:196–230` never asserts a leveled Musketeer body, an in-flight qualified Fireball carrier/pending cast, or a reachable Tombstone child/production payload in the snapshot/cut. The final qualified-card assertion examines the full mixed config, not the cut or a deployed entity. Random stepping may consume a carrier before capture; matching uncut/cut/pool values also cannot detect all branches retaining L11 for an unsupported fixture card (`:176–177` prints unsupported entries but does not reject fixture-card omissions). Capture deterministic pre-impact/post-spawn states as needed and assert the fixture's expected level stats and required qualified keys survive the cut. The actual-pool transport fix is source-correct, but its present result should be labelled bounded scripted transport parity, not full root/payload preservation. It uses original `R.native`/`R.meta` (`:182`), not the replacement from leaf_native, and only seat 0 / balanced / 25 actions (`:202–215`). This deliberately does not discharge parked metadata or learned-model equivalence questions.

3. **P1, existing acceptance gap — fair-information and exact-root evidence are still incomplete.** `bot/levels/gates.py:240–247` checks two equal planner views and equal configs for seat 0. It never calls either root builder or makes a decision. The sides/spell/cut gates build native states directly from differential snapshots (`:67–74`, `:118–160`, `:185–201`); they do not exercise `ExactLevelRoot.payload`. The new tower-shot test calls `tower()` directly (`bot/levels/test_configs.py:28–38`). The gate also does not test lower-level used-card support: L5 Clone/Earthquake/Tornado errors remain unsupported, and any actually playable occurrence must be rejected/kept out under the existing design rather than silently admitted.
