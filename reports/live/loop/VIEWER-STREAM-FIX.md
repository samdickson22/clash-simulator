# Complete viewer frames and optional mobile mode

The viewer proxy could forward a truncated upstream JPEG as a complete multipart frame. A local reproduction declared136,808 bytes but relayed68,404 bytes without JPEG EOI. The fix publishes only bounded complete, decoded JPEG frames and keeps the last good frame when the upstream fails. This proves a framing defect; it does not prove the cause of Sam's screenshot.

One latest-frame producer serves subscribers without per-client queues. Client writes time out after three seconds and do not hold the producer lock. The default stream retains source JPEG bytes and quality70. An unchecked Mobile low bandwidth option requests full-aspect images at at most360px width, JPEG50 and at most3FPS; it changes only viewer output, not capture or inference.
