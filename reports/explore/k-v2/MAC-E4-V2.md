# Mac E4 v2 requirements from K-v2

Updated 2026-10-10T05:05:12Z. Prepared on Linux only; no Mac access/transfer/live change. This owned note supersedes K’s latency/speed assumptions for the fixed K4 comparator. Existing Mac package and its pins remain read-only.

K-v2 requires **0.80× fleet per-core speed** as the minimum supported budget-equivalent per-core admission condition for at least−10pp versus K0-200 (upper paired95% CI≤−10pp). Tested qualifying cells: V160, V200. Point interpolation estimates 0.760×, with no qualification below the tested passing cell.

**Performance condition only:**0.80× is the minimum tested budget-equivalent speed meeting the loss gate. It does not qualify deployment. The reporting sweep failed the universal deadline+8ms return bound (16/15/7 W exceedances); full-pipeline latency and maintenance/poll gates must pass on the loaded Mac before admission. Neither drain removal nor the passing smoke proves a hard timing guarantee.

1. Build and pin an owned generic arm64 GIL-release/tick-cancellation binary after a separately authorized Mac session. Preserve combat source/templates/Python ABI/compiler/adapter/config pins. Linux native44874fd6 is provenance only.
2. Repeat125-state no-deadline screen8 action/score/root/RNG equality across1/4 workers. Require complete candidate/style/root contributions before common cutoff and original reduction/ties. Include exact preparation posterior/ledger/sample/RNG qualification and cutoff/resume tests, pre-cutoff scores collected late, zero/partial/exact-cutoff/late-worker tests, and late command/wait effects at20Hz.
3. Use one global four-worker scorer pool across the existing four belief roots; do not nest4×4 workers. WAIT/WAIT10 completes across all required roots before plays. Each worker has a private root and stops at its next cancellable simulation tick. Return at scoring cutoff without waiting on worker drains; do not publish partial/late scores or post-return mutable state. Exact public belief preparation must also be resumable/cancellable; do not move it outside the full timer. Defer cyclic GC during critical decisions only, meter its maintenance cost, and verify loaded packet-gap/end-to-end gates account for maintenance.
4. Benchmark per-core throughput against a pinned fleet-equivalent fixed work corpus and measure the complete four-root pipeline with actual perception/emulator load on four uncontended scorer cores. Include cold/warm observation, v1 fallback, belief, candidates, reconstruction, all roots/styles, reduction and real submission in the200ms timer with8ms reserve. Measure p50/p95/p99/max, cutoff/no-complete-play/fallback, every >200ms overrun and >208ms cut return. The one-root fleet sweep does not qualify the four-root Mac pipeline.
5. If throughput is below the minimum supported condition or full pipeline/tail gates fail, K4 has no supported−10pp claim for that Mac session. Report the measured speed and cutoff regime; keep a separately qualified fallback. No new one-core/default/student configuration is authorized here. The frozen K-v2 default remains the polled v1 only when no complete root score exists.
6. Preserve existing formal E4 real-gRPC/frame-to-submission/FPS/gap/command-acceptance/P4 gates and eight-match integration qualification. Loaded replay is insufficient. Account for real late submission in replay/game evaluation; report all overruns, never grant late actions immediate effect.

7. Qualify a GC strategy on the Mac: consider gc.freeze() after representative warmup, followed by tuned generation thresholds and bounded maintenance scheduling. Measure retained memory and peak RSS alongside collection frequency; freezing and threshold changes require the same score/posterior equality qualification. Record every maintenance pause with start/end monotonic timestamps, generation, game tick, scheduled poll deadline, channel availability and decision opportunity. Report count, p50/p95/p99/max, rate per real game minute, overlapping-opportunity count, skipped/delayed polls and pause-to-next-submission delay under actual perception/emulator load. Include maintenance in live end-to-end/FPS/packet-gap gates; moving it outside the decision timer does not satisfy those gates. The Linux study did not use freeze/tuned thresholds and cannot establish zero live opportunity overlap.

The deadline sweep holds an8ms reserve, so0.8/0.6 nominal headroom corresponds to0.792/0.583 scoring-budget ratios. Return/preparation and real-time game-tick scaling are not slowed by hardware emulation. The actual minimum Mac per-core speed cannot be measured without Mac access; this note states a supported lower-bound requirement and the loaded qualification needed to use it.
