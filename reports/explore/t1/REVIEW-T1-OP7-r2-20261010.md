## 2. F1 accounting: correctness

**Mechanism.**
- Each budgeted row is charged `own_delta + reaped_delta − min(reaped_delta, debt)`.
- When a generation disappears, its accumulated credit (everything charged to its subtree) moves to its last-observed parent as both debt and credit. Exits are processed deepest first.
- Parent lookup goes through the previous snapshot, keyed by generation, and requires `parent.start ≤ child.start`.

**Hand checks and synthetic probes** (the probe script ran from a separate tmp dir and has been deleted):

| Case | Expected | Charged |
|---|---|---|
| 4-deep chain, 100 real ticks (worker test) | 100 | 100 |
| Observed 5 s child reaped (standalone sample and block meter) | 0 extra | 0 extra, no sample stop |
| Unobserved child only | 70 | 70 |
| Delayed wait over 3 scans, plus an unobserved 30 in the same reap | 130 | 130 |
| PID reuse: child (start 102) charged 100 and reaped; a new same-PID child (start 300) uses 50 and is reaped | 150 | 150 |
| Budgeted → unbudgeted → budgeted chain (not reachable through `source()`) | 100 | 100 |

**Findings on the mechanism:**
- **No double subtraction.** Parent credit = own + (reaped − discount) + transferred child credit. When fully matched, that equals own + reaped, exactly what the grandparent's cutime will jump by. Ties at equal depth are independent.
- **PID reuse.** A new generation isn't in `last`, so it gets a fresh baseline and is charged in full if it was born after the window opened. A stale PID can't match through `bypid`, because lookup goes through the previous snapshot's generation.
- **The OP-6 meter change** is the same class. With zero debt it reduces exactly to the old `increment()`. Only the new phase uses it, and every block records its rule. Behavioural differences beyond removing the double count: N1 (rare under-count) and N6 (the persistent sample tracker's "born" reference).

### New findings

**N1 — LOW (fail-open, narrow, bounded). Debt that is never matched persists and discounts later CPU of unobserved children.**
- **Where:** `cpu_accounting.py:47-53` and `:68-69`.
- **Mechanism:** debt lives until it's matched or the parent generation exits. When a child's CPU never reaches its last-observed parent's cutime, the debt stays and later absorbs cutime from *other, never-observed* children of that parent. This happens when:
  - the parent exits without `wait()`, so a zombie child is reparented and reaped by init within the same interval; the debt then lands on the grandparent;
  - the parent ignores SIGCHLD or uses SA_NOCLDWAIT;
  - or the out-of-order scan race described below occurs.
- **Probe (a):** G→P→C. C is charged 100 live. P and C exit in one interval, and P never waited. Then an unobserved child of G uses 100. **True 200, charged 100.**
- **Probe (g), scan race:** a child is read alive while its parent already includes it. That sample is double-counted (200 vs 100), and the leftover debt of 50 then absorbs a later unobserved 50. The net total converges, but locally the sample is high.
- **Likelihood:** low for apt. `apt.systemd.daily` has no background jobs, unattended-upgrade, dpkg and apt wait for their children, and the race needs a child PID lower than its parent's. It's possible in ssh-family shells that `cmd & exit`. The error is bounded by CPU already charged for the orphaned subtree.
- **Disclosure gap:** the worker's residual ("auto-reaped/orphaned CPU may escape") doesn't describe this. Under-counting *unrelated* unobserved CPU is the case the ruling said must not happen.
- **Fix (≈3 lines):** expire unmatched debt after K scans, for example K=3. That still tolerates the tested delayed wait. Dropping debt over-counts, which fails closed. Add a test with probe (a).
- **Alternative:** disclose it precisely (C1).

**N2 — LOW (availability, fail-closed; by design and tested at `test_op7.py:200-206`). Block meters charge pre-block CPU of children that are reaped inside the block.**
- **Mechanism:** `begin()` builds the Accounting with no baseline credit (`apt_budget.py:154`, and the same in ssh). A child alive at block start has its *lifetime* CPU added to its parent's cutime when reaped, but its debt covers only the charges made inside the block.
- **Probe (b):** 100 ticks used inside the block, 600 charged.
- **Exposure:** there are 11 concurrent slots, and every block that starts in the middle of an apt run is exposed. In apt-daily-upgrade, `sh apt.systemd.daily` reaping `unattended-upgrade` can lump several seconds of pre-block python CPU into a block. At the first average check (60 s), 6 s is the 10% stop threshold.
- **The host sample tracker is not affected:** it lives for the supervisor's lifetime.
- **Fix:** seed each block's Accounting with credit for every row at begin: `credit[g] = cpu + child_cpu`. That is exact, since pre-window CPU is outside the window, and it removes a source of spurious stops. Combine it with the N1 expiry so a larger stale debt can't arise.
- **Status:** optional; it doesn't block admission.

## 3. `_apt` and argv0 spoofing analysis

| Vector | Result |
|---|---|
| **Trust anchor** | The kernel cgroup (`apt-daily*.service`, which only root can enter), real and effective UID from `/proc/status`, and an observed chain of root or helper rows that reaches a `root_command` root. An `_apt` process that passes must already be one apt spawned in that unit. |
| **argv0 is self-reported** | Inherent to the ruling. Any process that already meets the cgroup, UID and ancestry conditions can claim argv0 `/usr/lib/apt/methods/http` while running another image. The file check proves the on-disk file is trustworthy, not that this file is the running image. Accepted by 7c581dc5; the caps still apply. |
| **Symlink** | Probe: an argv0 symlink outside METHODS (`/tmp/…/evil-link → /usr/lib/apt/methods/http`) **is accepted**, because realpath lands in METHODS. That conforms to the ruling ("normalizes (realpath…)") and adds nothing beyond the point above. Hardening: apt always invokes methods with the full path `Dir::Bin::Methods/<name>`, so also requiring the lexical `Path(argv0).parent == METHODS` costs nothing (N4). The `https`→`http` and `mirror+*`→`mirror` symlinks resolve correctly. |
| **`..` / realpath escape** | `..` is rejected lexically, then `resolve(strict=True)` must land as a direct child of METHODS. `//`, `/./` and a trailing `/` all normalize to the same file. No escape. |
| **Writable directory** | The target's parent must equal the constant `/usr/lib/apt/methods`, which is root:root 755 on 05, as are `/usr/lib/apt` and `/usr/lib`. The code doesn't check the directory's own mode (N4). Swapping a link between the resolve and the stat would need root. |
| **TOCTOU** | The exe, argv0, cgroup and status are all read *before* the generation/ppid/owner/status recheck (`host_audit.py:45-69`). That is an improvement on r1, where exe was read after the recheck. A UID change between the reads drops the row. |
| **Non-EACCES errors** | ENOENT, EPERM, None and others → None → no exception (tested). On 05, I confirmed that `Path('/proc/<other-uid>/exe').resolve(strict=True)` raises errno 13. A zombie of another UID also gets EACCES, but its cmdline is empty, so `foreign_compute` skips it and the CPU is charged at reap. |
| **Real vs effective UID** | Both must equal `_apt`, and (0,0) for a root. The saved and filesystem UIDs aren't checked: a process with real = effective = 105 but saved 0 could re-elevate. Requiring all four fields to be equal costs nothing (N4). |
| **"Fails closed (stop)"** | A helper that fails the proof but whose argv0 is under METHODS is forbidden by `apt_command`, so it stops (tested). One with a non-METHODS argv0 falls back to the base rules: a stop only if it is compute-named or uses more than 0.1 s of CPU between two scans. That is the base guard's normal meaning of fail-closed. |
| **Residual** | `_apt` grandchildren with other executables, such as `apt-key` (sh) → `gpgv` under the gpgv method, get no exception, by the ruling. They stop only if they're alive across two scans and use more than 0.1 s. Unlikely; disclosed in OP7-T1.md. |

## 6. Other new items

- **N3 — INFO (qualification). Census scans cost more.**
  - **Measured on 05:** `processes()` over about 1295 processes takes a median 0.178 s at the base and **0.316 s** at 1c34584b (+78%). r1 was +18%.
  - **Cause:** two `/proc/<pid>/status` reads for every process, plus a read of `/etc/passwd` on each scan.
  - **Impact:** the cost lands on the census/supervisor CPU, not the measured cores, and `dt` grows a little.
  - **Optional optimization:** skip the second status read unless the first returned (0,0) or (`_apt`,`_apt`). A change to anything else gets no exception, so it fails closed.
  - Covered by C3.
- **N4 — INFO (hardening beyond the ruling, all free):**
  - require argv0 to be a lexical child of METHODS;
  - check that METHODS and its ancestors are root-owned and not writable by group or others;
  - require all four `Uid:` fields to equal `_apt`, and all four to be 0 for roots.
- **N5 — LOW (fail-closed gap). A v1 proof that lacks `ubuntu_apt` reads as unflagged.**
  - **Where:** `ssh_sensitivity.py:26-28`. supervise always writes the meter, so this only matters if a proof were corrupted.
  - **Fix:** when `ssh_family.cpu_accounting_rule == 'OP-7-observed-child-credit-v1'`, require `ubuntu_apt` with the same rule. In the ledger, check that both rules agree instead of taking the apt one (`:64`).
- **N6 — INFO (undocumented OP-6 sample difference). The persistent host sample tracker uses supervisor start as its "born" reference, where the old code used per-interval `now − dt`.**
  - **Effect:** a budgeted row that is missing from one scan and then reappears is now charged its full lifetime CPU in one sample. The old code charged it 0.
  - **When:** rows drop only when the recheck fails (ppid, UID or status changes mid-scan), which is rare for stable processes.
  - **Assessment:** the difference fails closed, so mention it in OP7-T1.md.
  - **Related:** the new status recheck turns an exit during the scan into a dropped row instead of a retained one, since `capture_uids` returns None. That's negligible.
- **N7 — INFO (doc).** The r1 paragraph in PLAN.md still says OP-7 authorizes "only UID0". The appended r2 paragraph supersedes it implicitly; mark the r1 text superseded when re-hashing at admission.
