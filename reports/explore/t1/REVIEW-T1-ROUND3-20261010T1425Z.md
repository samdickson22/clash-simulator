## 4. Conditions

**C1 (blocking, one line): per-game wall and CPU in stdout are a game-length proxy.**
- `run.py:304` prints `cpu` and `wall` for every game, keyed by a game id that names the arm, into the supervisor
  `{id}.log`.
- Per-game wall is close to proportional to decisions × deadline, so it is close to proportional to game length.
- The coordinator's N3 ruling seals game length like outcomes. Read per arm during reporting, this is the same
  outcome-correlated signal that removing ticks was meant to seal.
- I said in round 1 that per-game wall and CPU were fine. That predates the N3 ruling, so I'm reversing it here.
- **Fix:** print only `game` and `terminal` per game. Wall and CPU stay in the sealed game JSON. The block-level
  `wall_seconds`, summed over 8 arms, and the existing timing receipts are fine.

**C2 (freeze hygiene): `guard-decks.json` was produced by the round-1 selector.**
- Its `selector_sha256` is `32002f7d` (utc 13:43Z). The frozen `select_guard_decks.py` is `21125180`.

  identical; the response reports 3 decks, 17 cards and zero skips on 01, 03 and 08.

**N7: a dead host can't be inventoried.**
- `inventory` reads `launch.json`, `pids/` and `descriptors/` from the lost host's own phase directory.
- If the host is permanently gone, it raises `FileNotFoundError`. 127x02 died on 2026-10-07, so this can happen.
  The failure is closed, but the study then needs an amendment even though two hosts remain.
- **Fix, either:**
  - mirror these small files to the hub on every copy cycle, and let `HOST-LOSS.json` sit beside them;
  - or pre-register that a dead host's queue is classified by prefix: positions below the last mirrored launch
    index plus `slots` count as started and lost, and the rest are re-dispatched with their original seed.

**N8: inventory is not idempotent across phases.**
- Passing a phase that was already inventoried, together with a later phase, trips `assert id not in seen` on
  re-dispatched blocks. `replace.main` then writes the STOP file (fail-closed).
- Re-running a phase on its own re-queues its unstarted blocks a second time. That is harmless, because of hub
  dedup by id and ledger exclusion, but it wastes compute.
- **Fix:** state in the RUNBOOK "inventory only newly stopped phases", or skip ids listed in earlier
  `never_started_redispatched` outputs.

**N9: the release doesn't check the Mac summary's content.**
- `committed_mac_summary` checks commit and SHA, but not that the summary has `dry_run is False`.
- `reduce.py` also runs without `--mac-summary` under that release, and returns `DESCRIPTIVE_ONLY`.
- The coordinator signs every release, so this relies on the coordinator rather than being a hole. Still:
  - assert `dry_run is False` in `outcome_release`;
  - require `--mac-summary` when the reason is `committed_mac_summary`.

**N10: the 14-day escape trusts a self-reported time.** It uses the receipt's own `completed_at_utc`. Also require
that time to be no earlier than the committer time of `completion_commit`, minus a small slack.
