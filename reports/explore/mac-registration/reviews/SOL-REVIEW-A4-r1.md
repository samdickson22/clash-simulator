1. **BLOCKING: `student_reference.py:71`, `memory_check.py:27`, `memory_check.py:33`, `memory_check.py:59`. The Torch bootstrap runs twice per process.**
   `io.bootstrap()` calls frozen `tier_backend.setup_imports()`, and then `TierBackend.__init__()` calls it again. Both calls execute `torch.set_num_interop_threads(1)`. I reproduced the resulting `RuntimeError: cannot set number of interop threads…` in the pinned Torch environment, including through the actual frozen bootstrap and constructor. Student-reference computation and both memory-check paths cannot run.
   **Required fix:** arrange exactly one runtime bootstrap per interpreter without changing frozen e4v3 bytes. Add a regression test that keeps the real bootstrap behavior; the current hand-off test mocks both bootstrap and backend construction.
2. **BLOCKING: `stage_nocopy.py:48`. `cp -c` can silently perform a data copy.**
   Apple's implementation falls through to ordinary copying when `clonefileat()` fails with `EXDEV` or `ENOTSUP`. That is especially likely after the preceding hard-link attempt has failed across filesystems. The copied bytes pass SHA verification, and the wrapper wrongly records `method="apfs-clone"`, so the "never a data copy" claim is false.
   **Required fix:** call a clone-only API such as `clonefile(2)` directly, or use an API that forces cloning without fallback. Fail on unsupported or cross-device cloning. Test these failure paths and correct the amendment's staging claim.
3. **MAJOR: `seal_receipt.py:27`, `seal_receipt.py:36`, `student_reference.py:56`. Receipts are compared without verifying the current artifacts they describe.**
   I reproduced a concrete failure. After the synthetic compute and cross-check succeeded, I replaced `student-reference.json` with `{}`, and `seal_receipt.py` still produced a receipt with every check true. Its coverage check compares a receipt's count, not the actual reference keys. Likewise, `stage_inputs()` compares the conversion and assembly declarations, and `work_bundle()` hashes current files without requiring those hashes to match the declared outputs.
   **Required fix:** before computing and before sealing, verify current artifact hashes against their stage receipts. Check the actual reference keys against the agreement ids. Bind the actual assembled fixture, the converted index and container, the fixture digests, the selection plan and the pool metadata. Add regression tests for changed artifacts and mixed stages.
4. **MAJOR: `memory_check.py:57`, `memory_check.py:90`, `memory_check.py:93`; `seal_receipt.py:42`. The memory gate neither enforces nor binds its workload.**
   The memory checker accepts any nonempty Mac-profile agreement list. It can run fewer than 2,000 forwards and retain fewer than 2,000 inputs, yet still report `forwards_per_child=2001` and pass on memory consumption alone. The sealer binds the memory evidence only to the `states.pkl` SHA, which does not identify the agreement set: the same fixture can support different manifest selections.
   **Required fix:** validate the agreement size and uniqueness, assert the retained input ids in the main process and both children, and verify the actual forward counts. Bind the memory receipt to the reviewed sets, the backend bundle manifest and the converted fixture, and enforce those bindings when sealing. Summing three Linux CPU HWM values is conservative for the processes measured, but it is a proxy, not a demonstrated upper bound for Mac CPU/MPS memory.
5. **MAJOR: `macreg_io.py:94`, `macreg_io.py:180`, `stage_nocopy.py:59`. Frozen runtime provenance is not enforced.**
   The builder checks selected e4v3 files and the policy artifacts, but bootstrap checks the native module's path rather than its SHA. It neither verifies nor records the END runtime source manifest. The staging wrapper imports `prepare_bundle` without checking the required `a1c59fa3…` pin. The "END-pinned runtime" and the "frozen prepare_bundle" are therefore the caller's assumptions. The 300-state S comparison does not establish runtime equivalence for the remaining agreement states.
   **Required fix:** verify the frozen END runtime/source binding and the native SHA before using them, and record that binding and the expected package versions. Verify the staging package's frozen `measurement_files` pins before importing it. Keep all frozen files unchanged.

   **Required fix:** either stop and escalate in this case, or present it explicitly as an additional preregistered rule that needs coordinator adoption before the captures are opened.
