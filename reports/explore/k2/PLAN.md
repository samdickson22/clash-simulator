# K2 frozen exploration

Question: does two-worker anytime W at a 200 ms decision deadline retain at least 80% of four-worker W's improvement over K0? All arms are paired within this study: K2-200, K0-200, K4-200, 600 fresh seeds each against sealed v1, symmetric delay 27 and capacity 1. Five decks / 25 matchups, alternating seat, 12 seeds per matchup/seat. Same shuffled decks and game seed across arms. No Mac, live, heldout or gate admission.

Source derives from K-v2 e546e181 (plan), 75e2513d (exact preparation), dd692ef9 (final GC-deferring runtime). K/K-v2 files are read-only. Scorer changes only accepted search thread counts from {1,4} to {1,2,4}; persistent pool and phase bounds already honor thread count. K-v2's non-draining cutoff collector, immutable private roots, full-score admission, screen8 refinement, original order/epsilon ties, empty student hooks and public belief preparation remain frozen. Deadline begins before observation; cutoff is 192 ms with 8 ms reserve. Positive wall overrun delays command/wait/own availability by ceil(overrun*20) ticks. Every positive overrun is retained.

Run only on 127x03, nice 10/SCHED_OTHER, after K-v2's explicit release note and verified absence of its recorded supervisor/pool PGIDs and any K-v2 Python work. G STOP-03 stays retained; never restart or signal G. Check who at launch; 11 disjoint five-core slots 0–54 when empty, eight slots 0–39 otherwise. Each game narrows its own slot to K2=3 physical cores (two workers plus main), K0=1, K4=5. Supervisor/reduction use core 59. Qualification alone may use core 60 at nice 10; no timing on 60–63 or SMT siblings, no cache/controller changes. No work on 01/04/08/leased hosts; 05 is repository/command work only, never simulations. Owned setsid-f wrapper records all PID/PGIDs. Memory floor 24 GiB, owned STOP checked every 10 seconds.

Qualification requires 125/125 exact frozen screen8 actions/candidates/scores for 1,2,4 threads; exact one/two/four equality; 125 immutable roots under native zero budget; injected-clock no-drain/late-root/pool-reuse tests at two and four workers, honest-lateness tests, exact resumable belief ON/OFF, GC-window tests. Eight separate smoke seeds per arm (24 terminal games) are excluded. Smoke requires metadata, lateness, scheduler/core, capacity, paired-deck and no-in-window-GC audits; any observed timing tail is disclosed rather than outcome-dependent tuning. Reporting requires qualification, smoke pass, pinned runtime and committed/pushed plan/audit/source.

Reporting range 4503602307370496+[0,600); excluded smoke 4503602317370496+[0,8). Audit includes every inherited K/X/G range, K-v2 reporting/smoke, R3 reporting/smoke/regret reservation, noise-ceiling replay, formula-review evidence and helper offsets 0/13/100000..100003/271828..271829. R3 reservations came directly from its worker and will also be bound to its on-disk freeze/audit before reporting. No open-ended allocation can cross the reserved bank without a new audit.

Use 5,000 shared paired-seed bootstrap resamples, RNG 2026101003, unadjusted 95% percentile intervals. Report each arm's W/L/D, loss CI, paired loss change vs K0, cutoff rate/CI, positive-overrun distribution and tick histogram, wall latency p50/p95/p99/max, GC count/generation/distribution/pause per terminal game minute. Primary retention=(K0 loss−K2 loss)/(K0 loss−K4 loss), with the same shared resamples; report nonpositive denominator replicas and omit them from ratio CI. If point denominator <=0, retention is undefined. Also report the paired 80%-target contrast (K0−K2)−0.8(K0−K4) and K2−K4 loss change. Point retention >=80% meets the exploratory target; lower CI >=80% supports it confidently; upper CI <80% rejects it; otherwise disclose uncertainty. No tuning or early outcome inspection.

Cyclic GC is deferred only during timed decisions. Maintenance pauses are counted in game wall/CPU, without advancing simulated ticks or charging decision lateness. Frozen instrumentation has durations/generations/window flags but no pause timestamps or live poll/opportunity state: live overlap and loss penalty remain unknown. Fleet strength retention does not prove Mac compute headroom or live pipeline timing. R3 waits for explicit K2 release and no owned K2 PGIDs before stage 2.
