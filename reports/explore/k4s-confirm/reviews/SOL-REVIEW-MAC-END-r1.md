# SOL independent review: K4S Mac measurement and END, r1

**Verdict: REJECT.** Two producer/consumer incompatibilities prevent the intended Mac flow from running. Independent integrity defects also permit unsupported END inputs or invalid session evidence to pass. These need correction and an integration re-review before freezing F-8.

Reviewed worktree: `/mpac/sdicks02/repos/clasher-k4s-prep`, 2026-10-11. Review author did not implement this code. Governing sources read: PREREG-K4S-DRAFT-r3 (§1.4–1.5, §2.3–2.4, §4.5, §5.4), CONFORMANCE-r2 (N2, N3(b), F-8), RECHECK-r3 (R3/R5), TIERS r3 (§6–§7), K4S-SPEC (§4/§8), and the frozen TIERS helpers needed to trace execution. This review file is the sole authored artifact.

## Numbered findings

1. **BLOCKER — The SD1 validator rejects the shipped SD1 manifest.**
   - Location: `reports/explore/k4s-confirm/mac/k4s_logic.py:638` and `:644`; caller `mac/measure_k4s.py:334`.
   - Failure scenario: the actual `SD1-MANIFEST.json` uses `checkpoint.sha256`, `calibration.sha256`, and `inference_sources`. The validator instead expects top-level `checkpoint_sha256`, `calibration_sha256`, and `source_files`/`inference_source_sha256`. Calling it on the shipped manifest, with its actual SHA and the correct frozen checkpoint/calibration SHAs, raises `PreconditionRefusal: SD1 manifest does not bind the R3a bytes`. Every normal Mac attempt is refused. Merely adding the two flat SHA fields would still leave the actual inference-source inventory unchecked.
   - Suggested fix: validate the declared `clasher.k4s.sd1-manifest.v1` schema and its actual nested fields; verify the complete `inference_sources` map. Add a test that reads the shipped manifest instead of inventing a parallel schema.

2. **BLOCKER — END pooling does not emit the rate names consumed by the Mac reader.**
   - Location: `reports/explore/k4s-confirm/end_pool.py:47`; consumer `mac/k4s_logic.py:701` and `mac/measure_k4s.py:183`.
   - Failure scenario: pooling emits `cutoff_rate`, `no_complete_play_rate`, and `fallback_rate`. `check_fleet_reference()` requires `cutoff`, `no_complete_play`, and `fallback`, matching `GATE6_KEYS`. A synthetic, otherwise conforming 300-state, two-host, three-repeat pool with an independent-recheck SHA is rejected with `Fleet deadline rate disagrees with its counts: 1.0/cutoff`. Thus the END artifact cannot feed `measure_k4s.py` as promised.
   - Suggested fix: make producer, documented contract, validator, and gate-input builder share one canonical naming convention. Test `pool(...) -> check_fleet_reference(...) -> gate_inputs(...)` together with all five cells and integer counts.

3. **MAJOR — The END host statistic changes the frozen pooling rule.**
   - Location: `reports/explore/k4s-confirm/end_pool.py:35`–`:37`.
   - Failure scenario: this uses the median of host/pool per-state ratios. The frozen TIERS/T1 reference implementation uses the geometric mean of pooled-wall/host-median ratios (`e4v3/fleet_pool.py:56` and `:63`), under the pooling conventions inherited by r3 §4.5. A synthetic host that is twice as slow on 100 of 300 states and equal on the other 200 receives a median ratio of 1.0 and passes. The frozen-style geometric pooled/host ratio is approximately 0.90756 and fails. Reversing the ratio also changes which observations meet the asymmetric inclusive [0.95, 1.05] window.
   - Suggested fix: port the frozen geometric statistic and ratio direction without changing frozen files, using the K4S work-unit population explicitly. Document that population and test slow subsets plus inclusive boundary cases. If a different statistic is intended, obtain a preregistration amendment before using it.

4. **MAJOR — The END pool asserts reporting provenance without checking it.**
   - Location: `reports/explore/k4s-confirm/end_pool.py:20`, `:48`; driver `end_reference.py:69` and `:103`; reader `mac/k4s_logic.py:674`.
   - Failure scenario: the driver has no reporting-completion input; the pool has no committed counted-host inventory, load/slot evidence, technical-attempt classification, or reporting MHz input. It permits a single supplied host, then unconditionally writes `reporting_load_profile=True`. Omitting another counted host therefore silently excludes it. The driver's raw 1 Hz MHz samples are discarded by pooling, and no comparison to full-occupancy reporting rows or signed ratio is produced. END-RUNBOOK's operator instructions do not supply the missing machine-checkable evidence. After correcting only finding 2 in memory, the Mac reader accepts a 300-state single-host synthetic pool with none of this evidence and an arbitrary syntactically valid recheck SHA.
   - Suggested fix: bind committed completion and the complete counted-host set; require all original attempts and mechanical repeat classifications; verify slot 0, every background slot, priority and guard receipts; compare MHz only with full-occupancy reporting rows and retain the signed ratios. Validate the independent recheck receipt and its source binding rather than accepting an arbitrary SHA string. Reuse the frozen helpers read only where possible.

5. **MAJOR — END never performs the bundle/native/kernel pin validation claimed by its runbook.**
   - Location: `reports/explore/k4s-confirm/end_reference.py:60`–`:65`; `mac/k4s_backend.py:54`, `:69`.
   - Failure scenario: `backend()` constructs `K4SBackend` directly. `TierBackend.__init__` loads models, imports the native module and executes `states.pkl`; it does **not** call the separate `validate_bundle()` function. K4SBackend checks the separate K4 corpus SHA but imports arbitrary `--kernel`/`--scorer` paths without verifying their frozen SHAs. A changed bundle, native binary, or scorer can consequently become the fleet reference; cross-host agreement and K4S==K4 do not prove frozen identity. END-RUNBOOK's statement that TierBackend checks every pin is false for this call path.
   - Suggested fix: validate all fleet-profile bundle/runtime/measurement pins before backend construction or pickle execution, and independently bind native provenance plus the frozen K4S manifest/kernel/scorer and SD1 identity. Record these SHAs in the raw receipt and enforce equality in pooling. Do not modify the frozen backend.

6. **MAJOR — Pool validation checks row totals instead of complete per-state repeats.**
   - Location: `reports/explore/k4s-confirm/end_pool.py:22`–`:31`, `:40`–`:46`.
   - Failure scenario: declaring `repeats=3` does not require three entries in each wall/poll array. Deadline validation only checks a grand total, allowing one `(id, repeat)` row to be duplicated 900 times while all other states/repeats are absent. Cell headers need only agree across hosts; they need not equal the registered budgets/charge scales. In-memory reproduction with one timing per state, duplicate deadline rows, budget 999 and charge scale 1 still returns `pool_conforms=True`. This can distort both speed/poll medians and gate-6 rates. Checks expressed as `assert` also disappear under Python optimization.
   - Suggested fix: require the frozen 300-state inventory; exactly three finite positive timing observations per state; each deadline `(host, cell, state, repeat)` exactly once with repeats 0–2; actual bool rate flags; and each registered budget/charge scale. Use explicit exceptions and negative tests for missing/duplicate rows, invalid timings, and optimized execution.

7. **MAJOR — Reused TIERS receipts are sealed but never verified as committed.**
   - Location: `reports/explore/k4s-confirm/mac/k4s_logic.py:468`–`:475`; procedure `mac/K4S-MAC-PROCEDURE.md:126`–`:131`.
   - Failure scenario: admission verifies the current directory against a caller-supplied SHA and sidecar, with no commit/ancestry/blob verification. The default command immediately passes the just-created TIERS output after `measure_tiers.py` returns, before any commit step. An uncommitted or locally revised, re-sealed verdict can supply gate 0 and c_M=1.0, contrary to r3 N2's requirement to read committed TIERS receipts.
   - Suggested fix: bind a commit and repository-relative receipt inventory, prove the commit is admissible and each reused blob equals its committed bytes, and make the procedure establish that commitment before K4S admission while preserving the session lock. This need not change any frozen TIERS measurement file.

8. **MAJOR — The session reducer does not verify classification contents against their seal.**
   - Location: `reports/explore/k4s-confirm/mac/classify_k4s_failure.py:188`–`:193`.
   - Failure scenario: the reducer checks the classification directory's `receipt-manifest.json` hash, then reads `classification.json` without checking its hash against that manifest. Only session files receive `verify_pinned()`. Changing `valid`, `category`, or repeat eligibility inside `classification.json` while preserving `source_manifest_sha256` and the untouched seal passes this boundary. That allows excluding a slow valid session or admitting a technically invalid one, undermining the minimum/worst-input rule.
   - Suggested fix: verify the complete classification inventory, require a complete classification seal and inclusion of `classification.json`, then read the verified file. Require consumed session summaries to be present in their own verified inventories too. Add a test that mutates classification bytes while retaining the original seal.

9. **MAJOR — A cleanup exception can be classified as a valid session.**
   - Location: `reports/explore/k4s-confirm/mac/measure_k4s.py:696`; `mac/classify_k4s_failure.py:94`–`:115`.
   - Failure scenario: if `Session.close()` fails after the summary and completion receipt were written, main seals status `failed` and writes `cleanup-failure.json`. The classifier reads only `failure.json`, ignores `cleanup-failure.json`, and does not use manifest status to decide validity. With `k4s-complete.json.completed=True` and no other evidence it returns `valid`, despite the failed cleanup. A harness/load exception can thus enter reduction instead of receiving the registered technical-failure handling.
   - Suggested fix: include sealed cleanup exceptions in classification and reconcile status with completion. Test a completed measurement followed by backend/load/telemetry cleanup failure through both classification and reduction.

Gate 6 compares integer rates with the exact +2 pp margin, steps downward, and rechecks every gate. The c_M=1.0 branch uses the TIERS K4 verdict; eligibility implements c_M <= c*. Its kernel/SD1 "unfilled" note is stale relative to the shipped draft manifest, which already contains those hashes; `frozen=false` is appropriate while review remains open.
