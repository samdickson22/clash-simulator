# Diagnostic procedure — review before execution

The postmerge source is mergeae04c8846 (first parent frozen9fa, second11ff).
This procedure is new and **UNEXECUTED**. Source/procedure independent review
must bind the later exact commit containing these tools before any host command.
The final C1 full C56/main/pin hold remains; this is a bounded diagnostic job.

`tools/diagnostic_job.py stage REVIEW.json TAG` constructs a one-use source
capsule from exact committed bytes in the explicitly assigned integration
worktree. It rejects tracked WIP, non-ancestor B2, uncommitted/symlink/compiled
inputs, source/review hash disagreement and reused output. The typed independent
review must have verdict `APPROVED_FOR_DIAGNOSTIC_EXECUTION`, exact `commit`,
`base=9fa2ea993f5d0d26109b2fc2201db3c83dbf6089`, and `reviewed_sha256` equal to
the full engine tracked inventory plus every path in diagnostic_job.EXTRAS.
Review is source/procedure approval, never engine or broad coverage acceptance.

Staging contacts only127x08. A nonblocking serialized stage lock protects
one-use `/mpac/sdicks02/jobs/clasher/cards/c1/c1diag-YYYYMMDDTHHMMSSZ-rN`.
Every prior same-family job must have terminal cleanup receipt, no live recorded
PGID and no CPU lease. Otherwise execution fails closed; preserve and inspect,
do not retry a different tag to evade it. Safe regular-file extraction rejects
duplicate/traversing/link members. The copied source/tool/review inventory is
checked again. Historical inherited PID identities are observed read-only in
platform.json, without killing/restarting jobs or claiming old outputs as current.
Interpreter, CPU scripts and exact1.97.1 cargo/rustc binary hashes are retained.

The reviewed driver runs once through `nice -n15 cpu_job.sh4` with a clean
environment including correct USER/LOGNAME and capped threads. Admission hashes
of manifest, approval and platform are bound to an immutable command-line
admission SHA before launch. Inputs/controls and the one-use output stay local
to the new job; no runtime tree, active pin or older native is read/copied.
The actual PID/PGID/argv/UTC and source/control identities are saved remotely
and in a fresh local launch receipt. A failed stage retains its output/errors.

The driver verifies the direct lease4, nice>=15, admission/source/external
inventories, then runs fresh Cargo offline extension-module,gil-release build
with -j4. Only the resulting new ELF is copied to the private native directory;
build source, logs, exits, platform and binary hashes are bound in build.json.
The final-gate driver's previously reviewed Children/latching handler are reused
only as process-control helpers; its gate preflight/main is never called.
Every child has its own process group. Actual child wait exits, partial/final
phase exits and cleanup receipts are retained, including cancellation/error.

Four sequential probes run with actual import/source/data/native receipts:

A failed probe does not erase its raw output or prevent the other bounded phases
from collecting evidence, unless cancelled. No31-source/40-offset sweep or C56
is launched. The shared probe retains initial/paired/partial roots itself; the
worker captures available local battle/native roots from exceptional focused
frames in addition to partial result/log files. A native crash is a failed child,
never an inferred semantic pass. Actual imports are confined for clasher/native
to this capsule, and all loaded module file hashes are recorded. Admission,
source, data, native and external inventories are checked after probes as well.
Terminal output distinguishes diagnostic PASS/FAIL and always says engine
acceptance=false/finalC56=WITHHELD. Further selector/other-Spirit/generic-child
meaningful coverage and actual failures may require reviewed follow-up fixtures;
these four phases do not discharge all integration/final-acceptance obligations.

Before execution: inspect the independent verdict and exact bindings, verify
current source and job liveness/receipts, then invoke the exact reviewed stage
command once. Poll only the known PID/PGID and receipt/output paths with bounded
read-only checks; no watchers, duplicate build or sweep. Preserve every FAIL,
partial artifact and original approvals. New engine fixes require reproduced
evidence and fresh review; no extra semantic exemption. Rollback only isolated
integration changes; no deployed state or frozen base ref changes.
