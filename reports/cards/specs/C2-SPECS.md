# C2 card mechanics implementation specs

Research/specification only, written incrementally. No engine changes or commits. Verification below is an implementation acceptance plan, not a claim that fixes were run.

## Scope and conventions

Target is RoyaleSim's **cards-160402017-20261006.1** table and shipped calibration, not the adapter's default 15.535 table. Source roots: `P = engine-cards/py/src/clasher`, `N = engine-cards/src`, `R = /mpac/sdicks02/tmp/bot-upstream/RoyaleSim/crates/royalesim/src`. Functions below are relative to these roots. Evidence: `reports/cards/fidelity/{RESULTS.md,results.jsonl,scenarios.py}`, `reports/cards/stats/BALANCE-SIZE.md`, `reports/cards/native-diff/RESULTS.md`, and `reports/cards/batchA/RESULTS.md`. The fidelity runs used older r1 Python; the implementation target is the current worktree including Batch A. Measured pairs are **ours / RoyaleSim**, level 11; event ticks are relative to command tick 100, at 50 ms/tick. Base stats explicitly labeled below are level 1.

Arena order uses this worktree's `gamedata.json` `unlockArena` resolved through `items.arenas[].arena`: Electric=11, T=12, Arena13=13, Arena14=14, L1=15, L2=16, L4=18. This is the requested data-version order, not a claim about today's live unlocks. Tie order is stable by card name.

### Implementation contract for every mechanic

- Python owns decoded configuration. Export each new mechanic through `engine-cards/differential.py` and its snapshot adapters; Rust consumes that exported config, never independently reads a second balance table. Include nested child templates, levels, projectile payloads, explicit target masks, and timing units.
- Mirror Python's entity iteration, first-update, damage, death and cleanup order in native. New private state must round-trip in Python/native snapshots and clones; match allocation/next-id order as well as public HP and positions.
- All additions must be opt-in to these named cards/subunits (or an explicit new decoded mechanic), with absent fields inert. Native fields need `serde(default)` and default omission (`skip_serializing_if`) as in Batch A, so pure C56 snapshots stay byte-identical. Do not replace shared targeting, damage arithmetic, ordinary clocks, knockback or death-spawn defaults globally.
- Verify Python ↔ native digest **every tick** using `reports/cards/batchA/tools/probe_native_scen.py`, then run the existing C56 gate. The native-diff baseline already has IceGolemite alias/death-area, mixed attack-clock, dash-target movement, chain-hook recipient, Mega Knight cancellation, Mirror payload, Poison immunity and noninterrupting-freeze defects; do not count them as C2 fixes or silently bless them. Compare unchanged C56-only baseline fixtures separately.
- Stats belong in the separate stat overlay. A mechanic fix alone need not make a whole scenario PASS when a listed stat mismatch or established shared-C56 timing residual remains. Each section identifies the observable that should flip; use full PASS only after overlay + mechanics and explicit residual accounting.
- No battle runs or builds have been performed for this report; only light single-process source/data inspection and document checks. Numeric symptoms come from supplied evidence; source-derived expectations and proposed focused probes are identified as such. Do not treat an unexercised ability as measured.

### Priority

Implement base-unit mechanics and death releases first; champion buttons are a lower-priority follow-up. Measured no-button gaps needing only stats are **EliteArcher**, **GoldenKnight**, **RageBarbarian** and **GoblinMachine**. Lumberjack's active death-area path already decodes the 130% buff correctly; GoblinMachine's rocket is absent from the reference too. SuspiciousBush, Collector and Drill are not stats-only.

## Arena 11 — RamRider (Ram + snare rider)

**Symptom.** One Ram versus Ram + rider; HP `[1766] / [1766,593]`, attack `[250] / [271,104]`, both ready at 20. Bridge tower totals at 10/20/30 s are `1001/2001/2001` versus `1084/2168/2168`.

**Root / classification.** Mechanics + independent Ram damage stats. `P/factory/mechanic_detector.py:detect_mechanics_from_data` only recognizes a spawner with `spawnPauseTime`; the Ram's `spawnNumber=1` and embedded rider lack that field. `P/battle.py:_spawn_troop` never creates an attached unit. `R/card.rs:convert_attach`, `R/state.rs:spawn_riders`, `carry_riders`, `rider_deploy_lockstep`, `riders_die_with_their_mounts` implement it; `R/target.rs:can_target` handles troop-only selection and buff deprioritization. This is not a periodic summon or an extra Ram attack.

**Python change.** Decode explicit Ram attached-rider spec (the compact export omits `SpawnAttach`, `TargetOnlyTroops`, `DeprioritizeTargetsWithBuff`, and immunity metadata; restore by named object). Create exactly one rider immediately after its mount, same owner/unified level and spawn point; give it independent target/attack/projectile state, 593 HP/104 damage at level 11, range/sight 5.5, hit/load 1100/700 ms, muzzle 0.8 tile. Mirror mount deployment. Rider has no autonomous walk, collision/separation, forced movement, targetability, spell/damage reception, or curse reception. At the **start** of movement copy the mount's previous-tick point (zero offset here), so movement does not carry it to the new point until next tick; attacks use this carried point. Mount death kills rider in the same tick without requiring HP damage and leaves no dismount troop. Rider attacks enemy troops on either layer, never buildings/towers. Prefer troops without BolaSnare over those carrying it; already-snared troops remain fallback candidates. Whenever BolaSnare lands or refreshes on the rider's current target, clear only target/lock in that resolve boundary and rescan next target pass **without resetting attack progress**, preserving 22-tick bola cadence (`R/state.rs:drop_deprioritized_targets`). Bola projectile speed 600, damage base 41; on impact apply only movement ×0.30 for 2000 ms, refresh same buff without stacking; attack/spawn axes stay 1.0. Keep Ram building-only charge and river jump; restore charge multiplier 200 if missing. Overlay Ram base damage `98→106`, special `196→212`; do not scale rider damage with the Ram's attack delta.

**Native change.** Add optional attachment config + mount-id/offset state in `N/lib.rs`, create child through `N/spawn.rs`, run independent `combat_one`, implement the movement carry and death coupling, and exclude attached bodies in targeting, area and damage/effect gates. Extend projectile buff config (`N/projectiles.rs` / `scope.rs`) with the movement-only snare and named buff identity needed for target preference; export everything through `engine-cards/differential.py` and spawn snapshots. Do not approximate by firing a second projectile at the Ram's tower target.

**C56 risk.** Target/effect/collision changes are global sites. Gate each on `attached_to` or explicit rider target policy, absent for C56. Do not change ordinary slow decoding globally. Goblin Giant is a separate attachment consumer and must opt in explicitly, not acquire Ram's troop-only targeting.

**Verify.** `RamRider/{alone,knight,minions}` should gain one rider at birth/ready tick 1/20; Knight/Minions take bola damage and movement snare. Overlay flips tower damage to 271 normal/542 charge and listed bridge totals. Add both-seat probes: no enemies means no bolas at towers; two troops prefer unsnared; after 40 ticks an unrefreshed snare expires; direct spell on rider does nothing; death removes both. Reference binding tests: upstream `tests/test_ram_rider.py`.
