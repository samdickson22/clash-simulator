## Tracker and development

The tracker accepts public events and visible body token/positions, never engine identities, actual opponent deck/hand/resources or engine RNG. Perfect-event mode uses exact finite public derivation. Noisy resources use the full integer 0..100000 lattice with exact phase regeneration and cap transitions. Missed-spend transitions run during gaps; event accept/reject and measured label-confusion alternatives handle both over- and under-spending ledgers. Measured miss/spurious/confusion and board precision supply priors, scaled to each event level. A persistent uniform component prevents collapse and resource feasibility reweights it. A separate deck-free cycle beam merges equivalent queues, reserves an abstract unknown component and transfers pruned mass into it. A fixed lag fuses event and board evidence without duplicate spends. Board evidence requires persistent spatial tracks and groups multi-body spawns.

Fresh script-v-script development traces (no S2 confirmation trajectories) will provide public packets and scoring-only truth at 10-tick intervals. Development indices 0..27 train/calibrate; 28..55 validate. Per-level interval expansion may be set to the 90th percentile of calibration noncoverage distance, with width/coverage/MAE reported on validation. Other development changes must be documented before freeze. Never tune against confirmation. Recorded original P16 games test exact equality with srp-public and DerivedD1. Synthetic tests cover missed/spurious/confused events, cap/phase transitions, fallback retention, board duplicate suppression, and hidden-deck/RNG invariance. Pilot all seven cells outcome-blind; check anchor equivalence to S2 configuration where applicable.
