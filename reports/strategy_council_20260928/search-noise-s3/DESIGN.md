# Tracker v2 design and limits

The tracker boundary accepts public event candidates and visible body token/position triples. Static card templates map body types to possible cards. No entity ID, hidden card list, actual opponent elixir, combat clock, or engine RNG is accepted. Search root hidden identities are sampled from the frozen train prior, never read from the match.

## Resource inference

Noisy resource inference is a full distribution on the engine's 100,001 integer elixir values (units of 0.0001). Phase transitions add 178 units per tick through tick 2400, 357 through 4800, then 537; shifts collect cap mass exactly. Accepted events subtract public cost with four-tick, three-point timing quadrature. If the ledger cannot afford a trusted play, its accepted branch is lifted to the public minimum cost and then debited: an explicit upward resynchronization. This avoids rejecting a real observed play solely because a stale ledger is too low. The update is a robust mixture filter, not an exact Bayesian action-policy likelihood; rejected events preserve the previous ledger. Measured confusion pairs provide alternative labels. Missed-play transitions run during all event gaps, including gaps without contradictions. Cost priors come from the train deck prior. Event-rate estimation uses only the public detected count, smoothed with four events over a minimum 20 seconds. The measured miss rate scales this hazard; an initial development factor of 0.25 accounts for board recovery. Noisy transitions retain a uniform contamination component (0.0005 per second; 0.002 per event), enabling both higher and lower ledgers to recover through affordability conditioning. The posterior cannot discard a resource value by beam truncation.

A 32-tick fixed lag replays pending evidence. Event execution time is estimated as delivery minus six ticks; body birth time as first sighting minus five ticks. These are noisy estimates, not leaked execution times. Board tracks match token and position within 1.5 tiles, survive 20 ticks of disappearance, and need three sightings. Multi-body births sharing possible card identities within 40 ticks are grouped. Event/body cues within 24 ticks fuse into one play, with the joint false-positive probability used as soft confidence. Unmatched body confidence uses Bayes odds: miss × entity precision divided by (miss × entity precision + 1 − entity precision). Entity precision is 0.922. Event association history lasts 120 ticks, so late bodies can be recognized without charging a second spend. The simulator's detection model lacks stable visible entity IDs; the tracker never uses row indices as identity.

The nominal 90% interval is the equal-tail resource interval plus a radius learned solely from fresh calibration traces. Validation separately checks this calibration. Perfect mode disables noise transitions and uses exact finite derivation, so it does not accumulate contamination or calibration width.

## Hand and cycle

The noisy cycle mixture uses deck-free D1 state: public revealed identities, ordinary queue, pending refill and last public card. Accept/reject/card alternatives create branches. Equivalent queues/refill/revealed sets merge. The top 47 branches are retained and all pruned weight transfers to a reserved abstract unknown queue; its minimum unnormalized weight is 0.002 per event. This component represents lost synchronization and can regain identity concentration through subsequent consistent plays. Its uncertainty is explicit rather than silently removed by renormalization.

Resource and cycle beliefs are factored: their cross-correlation is approximate. This is a deliberate computational tradeoff against S2's enormous per-branch finite deck-order arrays. Sampled roots pair resource and cycle draws. Resolved-hand concentration is the summed mass agreeing on a fully known hand, with threshold 0.90; unresolved hands never count as concentrated. The old all-branch agreement diagnostic is also retained. For ELT, the reported mass is a conservative lower bound obtained from resolved branch hands; legacy already exposes its best resolved hand probability.

Public-unit births are soft evidence of a card, not proof: spawners, death spawns, fast deaths, delayed deployment, phantoms and track switches can mislead this model. Development diagnostics must establish whether the resulting errors are calibrated. No claim of live-client certification follows from this simulator experiment.
