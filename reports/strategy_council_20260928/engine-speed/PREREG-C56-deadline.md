# C56 deadline search prospective registration

Written before Stage 5b evaluation games. Stage 5 results are historical context, not new evidence. No confirmation outcomes will be used to change the player or analysis.

The candidate uses the unchanged Stage 5 public sensor, derived-state belief, train-only human prior, synthetic public reconstruction, candidate set, RNG and search cadence. Native search averages all three styles for each completed candidate, horizon 160 and interval 10. Live defaults are a 0.200 second wall budget measured before sensor conversion and two native candidate workers. Script top choice is the legal fallback. Only complete three-style scores count. The reduction uses priority order and the Stage 5 1e-9 tie tolerance. Scheduling may change the completed candidate set under pressure, but not selection for the same completed set. The baseline uses the Stage 5 sequential native search with no deadline.

Primary test: 128 fresh matchups, both seats, 256 terminal games, deadline player versus Stage 5 player. Seven human C56 deck families receive 19,19,18,18,18,18,18 matchups. Planning decks are frequency sampled from eval/eval_ood human perspectives; opposing human decks are sampled from train. Paired seats retain deck assignment to player role, swap world seats, and use the same world seed. This is role holdout, not deck-identity holdout. Each player receives only its own public packet, own HUD and opponent public events. Both choose before fixed seat 0 then seat 1 action application. Champion ability events are included in opponent public history.

Primary pass requires pooled score >=0.47 and paired-matchup 95% bootstrap lower bound >0.42, AND no deadline-player decision above 0.250 seconds. Wins score 1, draws 0.5. Confidence intervals use 10,000 percentile bootstrap samples of paired matchup means, NumPy RNG 40404043. No optional stopping, outcome exclusion or interim strength analysis. Report all failures and rejected commands.

Continuity test: 64 additional fresh matchups, both seats, 128 games against unchanged C56 balanced/pressure/defense scripts in round-robin assignment. Same public inputs and search parameters. Report score and paired-matchup CI descriptively; no extra strength gate.

Timing uses all 384 terminal games, exceeding the required 64. Report all-decision and searched p99/max, >250 ms count, deadline truncations and fallback count. Include public sensor, history assimilation, candidates, reconstruction and native work. Exclude pregame resource setup/warmup only. Baseline decision timings are reported separately and do not count as candidate overruns. Use at most three nice-10 game processes, with two native workers per candidate search. Record process/load evidence at launch and per game; do not stop or alter unrelated host jobs.

Before launch, freeze schedule.json, seed-audit.json and evaluation-manifest.json with SHA256 pins. Audit fresh world and player-derived seed ranges against all historical report JSON/JSONL seed fields, report text and NPZ seed arrays/embedded metadata. Pickled game roots rely on their JSON plan/gate provenance. Reuse no historical evaluation seed. Registration and exact schedule must predate all new evaluation games. No evaluation begins until all 200 Stage 5 roots reproduce the recorded trace hashes with 1,2,4 workers and focused deadline tests pass. Source pins are checked at worker startup and before every game. Resume only missing receipts from the same manifest; never overwrite completed outcomes.

Any source or parameter change after confirmation starts invalidates admission under this registration. Record the failed run rather than silently restarting or selecting a favorable subset. A cooperative deadline cannot guarantee realtime scheduling on macOS; observed zero overruns is a required empirical gate, not a universal realtime claim.
