# Local pilot orchestration

`configs/council-pilot-local.toml` validates against the staged native data and immutable training/development/acceptance deck files. `scripts/run_council_pilot.py` prints its plan by default. No gameplay fitting has been launched.

The configuration preserves the signed actor: width 128, four heads, four actor layers, two critic layers, LSTM 256, public contract 4, semantics 4, four history slots, eight seen-card slots and five-tick decisions. It uses gamma 1, GAE lambda 0.95, potential coefficient 0.05, learning rate 1e-4, clip 0.2 and two PPO epochs with the existing approximate-KL early stop at 0.02 and no learning-rate annealing. The scripted warm-start arm first runs 20 value-only updates with the actor frozen (scratch arm: 0); see `m0/merge-audits/README.md`. Recurrent reconstruction uses exact public episode prefixes in both collection and PPO.

Local execution uses two CPU workers with two environments each, one Torch thread per actor worker, two learner threads and two sequences per minibatch. A full 128-step collection retains 512 learner decisions. Opponent decisions do not count toward that total. The last chunk shortens at exact decision milestones; minibatch sample accounting therefore follows the actual chunk length. Three seeds, each with scripted and matched from-scratch initialization, target five million decisions per arm. Checkpoints at one million and five million decisions use stable decision-count names.

The runner invokes the complete-game warm-start command before either arm, records its matched random-control receipt and freezes the same initial opponent pool for both arms within a seed. Warm-start retries retain the control checkpoint named by the completed result receipt. Each match samples a public-script or initial-policy opponent during the first million decisions. Thereafter the pool uses the implemented 25/50/25 script/history/current mixture. Workers keep the selected opponent and its weights fixed for the match, isolate opponent RNG and log assignments. Saved learner checkpoints enter retained history through atomic pool publication. Repeated publication is idempotent and cannot roll generations backwards.

At reset, the level schedule retains nominal level 11 before one million decisions. Afterward, half the sampled games retain nominal levels and half draw card/tower levels 10–12. Levels remain fixed within each match. The schedule is implemented, but the current admission API only issues level-11 receipts. The mixed-league phase refuses those receipts. Expanded-level coverage and an evaluator-issued extension are required before that phase runs. The receipt representation is being prepared for extension before the initial source freeze; allowing a level in the representation never grants that scope. Source/config changes still cannot silently reuse an old freeze or checkpoint identity.

The fixed stochastic evaluation matrix contains 516 held-out games per checkpoint across three public-script styles and nominal/mixed levels. A separate fixed Hog 2.6 slice adds 192 games. Initial and learned checkpoints use identical frozen evaluation seeds. At the one-million diagnostic, both initial and learned checkpoints run a smaller development-role matrix plus the Hog slice. Final acceptance-role evaluation occurs after fitting. The runner retains per-game seat, matchup, level and outcome records; it does not infer promotion from the legacy aggregate binomial interval. Paired, subgroup-aware strength analysis and Tier B remain coordinator responsibilities. PFSP, exploiters and the optional oracle arm are later work, not enabled pilot features.

Fitting requires the evaluator-issued SQLite admission record, complete sealed branch evidence, matching source/data scope and the requested levels. A JSON success string is insufficient. The trainer checks its configuration and semantic checkpoint buffers before fitting. The ruleset hash is saved in every PPO checkpoint. The old training-package source manifest is not used as the new execution freeze; only its immutable data/role copies are reused.

A single-run lock and persistent local resource ledger enforce the agreed 4,608 CPU-core-hour and 72 accelerator-hour ceilings. Charging is conservative allocated task cores multiplied by job wall time. CPU-only jobs charge zero accelerator time. Warm start, PPO and evaluation share the ledger. Timeouts terminate only the launched task's process group. Checkpoints retain remaining-budget snapshots. Interrupted jobs with an unobserved end receive an explicit conservative accounting record; a still-running prior child blocks a duplicate launch.

After source integration is complete, the coordinator can write the source pin file with:

```sh
.venv/bin/python scripts/run_council_pilot.py --config configs/council-pilot-local.toml --freeze-source
```

Gameplay execution additionally requires `--execute` and the evaluator-issued receipt in the configured phase slot. The optional `--admission` argument must match that slot. Nominal and mixed-level receipt paths are declared before source freeze; issuing the later extension does not alter the stable training recipe or resume identity. Use `--phase smoke`, `--phase nominal` or `--phase mixed-league`; optional `--seed` and `--arm` select declared runs. The smoke has a 100,000-decision ceiling and continues through the same checkpoint lineage. Nominal and final phases evaluate automatically. The source-freeze command refuses to overwrite an existing freeze.

Validation passed 140 focused tests in 13.31 seconds, including real two-worker transport, learner-only accounting, immutable opponent assignment, exact milestones, level reset behavior, rejected fake admission, budget persistence/locking/timeouts, recurrent likelihood, legacy inference and synthetic warm-start orchestration. Ruff and `git diff --check` passed. `pytest.log` records the command/results; `../validated-plan.json` records the validated no-fit plan. No gameplay-label collection, policy-training job, native calls, cloud resources or commits were produced by this orchestration workstream.
