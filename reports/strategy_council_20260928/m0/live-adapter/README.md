# Live adapter boundary repair

Repaired the duck-typed `LivePolicyInputs` to include own accepted-play fields and entity/hand level fields. They default to `None` for legacy policies; v2+ receives explicit known/unknown accepted-play values, v3+ entity levels and v4+ the five own-card levels. The current public frame contract accepts optional measured levels/confidence and confirmed own control history. These additions do not default absent measurements to level 11, infer acceptance from submissions or fabricate missing lifecycle information.

The three failures seen in the broader integration run came from a preexisting interface mismatch: `HEAD:src/clasher/rl/model.py` already declared `own_last_play_ids` and `entity_levels`, while `HEAD:src/clasher/rl/structured_live_adapter.py` had neither. Adding v4 hand-level fields made completeness of this old duck-typed boundary more consequential; the original own-history omission was not introduced by M0.

Validation: `python -m pytest -q tests/test_rl_structured_live_adapter.py tests/test_rl_live_inference_contract.py` completed with **40 passed in 2.36s**. This includes nine new cases proving measured body/tower/hand/next levels reach the actor, changing an own level changes logits and recurrent state, unknown levels and accepted plays remain unknown, submitted actions cannot establish acceptance, malformed measured values are rejected, and the unavailable opponent-history contract fails explicitly. The original conversion/state tests and import-isolation test now pass. Focused diff check passed.

This adapter is not operational deployment-ready for the council preset. Match lifecycle is absent from its current sensor input, so masks remain wait-only. It also continues to reject models requiring accumulated opponent history, including the council preset's four history and eight seen-card slots. These guards remain explicit. This repair validates transport and model inputs, not camera recognition accuracy, native execution or playing strength.
