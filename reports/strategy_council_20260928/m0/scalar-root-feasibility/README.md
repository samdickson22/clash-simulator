# Scalar development root-selection feasibility

The 32-request development bank with seed **260928901** selected **19 roots** and retained **13 no-eligible-root outcomes**. There were no execution errors, redraws or replacements. Selection took 48.6 seconds and inspected 4,491 public packets while the prefix controllers issued 413 scalar commands.

| Requested context | Selected | No eligible root |
|---|---:|---:|
| Bridge contact | 8 | 0 |
| Own-half threat | 5 | 3 |
| Contested board | 4 | 4 |
| Enemy cluster | 2 | 6 |

Selected roots span 14 of the 16 focal cards and balance seats 10/9. Neither IceSpirit nor Tesla found a qualifying root in its two requests. The first eligible roots ranged from tick 95 to tick 1240. All original requests, prefix decisions, diagnostic counts and selected public packets are retained under `seed-260928901/`.

Tactical context alone was often present. Across all requests, 2,089 scanned packets matched the requested context, but only 156 had a complete candidate set under the existing eligibility rule; the focal card further reduced selection. For example, the failed Fireball/contested request had Fireball in hand for all 241 observations, but it was publicly playable in only 12, and only 15 context-matching observations admitted the complete candidate set. This indicates that the current spending prefixes, affordable-alternative requirement and focal/context pairing deserve design attention before expensive collection. It does not establish which change would improve consequential candidate coverage.

The helper uses the current public root selector and four declared candidate roles, the requested public prefix styles and five-tick cadence. Its game-data authority is the opened native capture's exact ruleset, SHA256 `daa58b28cf4e45d753e83ca69a76794285b63704e62363ee58e617af3a30ecc3`. Every new episode/family ID, episode seed, episode design hash and native config hash was checked disjoint from the reserved prospective bank/configs. The generated native configs are metadata only and were never submitted.

This is **scalar-only design feasibility**. Initial hands use the first four cards of each declared ordered deck, with the remaining four in the cycle. Equivalence to native initial hand shuffling is unproven. The native data file was used without gameplay-stat edits. Exact scalar level values are available to the public projection; this is not new native own-card level measurement evidence.

The source manifest records five unrelated package files changing during the run (`council_opponents.py`, `council_pilot.py`, `readiness_capture_ownership.py`, `readiness_transport.py`, `train_recurrent.py`). The battle, data, public-controller, observation and root-selector sources used here did not change. Full source hashes are retained; these unrelated edits do not make the result fresh or acceptance evidence.

No candidate continuations or outcomes were evaluated. The four agreed continuation conditions are declared in the bank for a later study. Consequently this result does not measure non-wait outcome separation, native coverage, admission, playing strength or teacher-label quality. A small continuation subset remains pending the coordinator's resource-window approval.
